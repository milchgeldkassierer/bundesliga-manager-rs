# Match engine and match-day presentation (segment 1310, match helpers in 1f9d)

Spec for a bit-exact port of the match day of `BMMAIN.EXE`. It covers every function in segment `1310`
(38 functions) and the six functions of segment `1f9d`. Segment `1f9d` is also specced in full by the
AI area ([ai.md](ai.md) §2). This document repeats the two result-deciding functions (`1f9d:08e9`,
`1f9d:0c3b`), which were verified independently against the disassembly, and summarizes the other four
with references.

Related specs: [rng.md](rng.md) (`random_range`, LCG), [state.md](state.md) (save blocks and
records), [stats.md](stats.md) (league table update `3a41:2d33`, AI scorers `24a4:1662/14d4`),
[../tore.md](../tore.md) (goal-scene playback `24a4:05ec`).

## 0. Conventions

* Addresses are Ghidra addresses in `/unpacked/BMMAIN_unpacked.EXE`. `DS:xxxx` is DGROUP (`5cb3`), and
  `FAR:xxxx` is the far data segment (`5238`). The selector used by each access was resolved from the
  selector table `DS:98d6..a146`.
* Types: `u8/i8/u16/i16/u32/i32`. All arithmetic is 16-bit unless stated otherwise. `(i8)x` means a
  sign-extending `CBW`, and `(u8)x` means zero extension. `/` and `%` are C (truncating) signed division,
  matching `IDIV`, unless marked unsigned. `ldiv/lmul` are the MSC long helpers `_aFldiv`
  (4a01:1a4c) and `_aFlmul` (4a01:1ae6), both 32-bit signed and truncating.
* `rr(lo, hi)` = `random_range(lo, hi)` (176b:0cc7) = `rand() % (hi - lo + 1) + lo`, with 16-bit
  signed arithmetic ([rng.md](rng.md)). **Every `rr` call below is listed in execution order.** `rr(x, x)`
  still consumes one `rand()`.
* `clamp(&v, lo, hi)` = `clamp_int` 4091:1009 (signed 16-bit: `if v < lo then v = lo`; `if v > hi then v = hi`).
* `absdiff(a, b)` = `long_abs_diff` 4091:10d5 = `|a - b|` on `i32`.
* `squad_count(m, f)` = `squad_count_by_flag` 4091:1109. It walks the first `n = (m == 4 ? 12 : 24)`
  player records of squad `m`. `f = 0` counts records with `id != 0`, `f = 1` counts the players on the
  pitch (`0 < slot < 12`), and `f = 2` counts the substitutes (`slot >= 12`). The result is a `u8`.
* `mgr(m)` = manager record `FAR:2242 + 0x30a*m` (save block 13). Offsets below are relative to
  `FAR:2242`, so `mgr(m).team` = `FAR:2260 + 0x30a*m` (`+0x1e`).
* `club(t)` = club record `FAR:3066 + 0x22*t` (save block 15). `player(m, i)` = `FAR:774a + 0x34*(25*m + i)`
  (block 18). `pdb(id)` = player database record `FAR:57dd + 0x25*id` (block 17).

### 0.1 Records used by the match engine

`club(t)` (34 bytes, the fields used here):

| Off | Abs (t = 0) | Type | Meaning |
|---|---|---|---|
| +0x00 | 3066 | char[20] | club name |
| +0x17 | 307d | u8 | base strength, used as `value - 44` |
| +0x18..1a | 307e..3080 | u8[3] | **skill** per line (0 = defence, 1 = midfield, 2 = attack) |
| +0x1b..1d | 3081..3083 | u8[3] | **stamina** per line. Strength loses `10*minute/(stamina+1)` |
| +0x1e..20 | 3084..3086 | u8[3] | **extra** per line (AI clubs drift in 45..55) |
| +0x21 | 3087 | u8 | flags. Bit 7 = show "goal elsewhere" flash for this club |

`player(m, i)` (52 bytes, fields used here): `+0` red cards, `+1` yellow cards, `+2` yellow-red cards,
`+3..+5` goals per competition (league, DFB cup, Europe), `+6..+8` appearances per competition,
`+9` flags (bit 0 = sent off/suspended, bits 0-1 checked as "unavailable"), `+0x0a` lineup slot
(1..11 = on pitch, 12+ = bench, 0 = not selected), `+0x0d` suspension games, `+0x0f` player id
(`pdb`), `+0x10`, `+0x11`, `+0x12` attributes, `+0x13` condition (clamped 50..150 per match),
`+0x15` match rating (reset to 0 per match), `+0x19` (i8) side, `+0x1a` (i8) role (7 = keeper),
`+0x22 + 2*k` (u16) goals in competition `k`.

`pdb(id)`: `+0x1f` u8 (keeper skill; `/25 == 0` means not a keeper type), `+0x20` u8 (preferred
side/foot), `+0x22` u8 league goals (top-scorer list), `+0x24` u8 club.

### 0.2 Competition and pairing addressing

* League tier `L` in 0..2. `DS:225a[L]` (i8) = current round (1-based). `DS:225e[L]` (i8) = number of
  teams. `DS:2262[L]` (i8) = number of rounds. `FAR:535a + 20*L` = team ids of the tier (block 32).
* **League pairings of the current round** `FAR:4b5e + 20*L + p` (home) and `+p+1` (away), with `p` even.
  They are regenerated by `league_team_range(L, round)` 3a41:10e3 (stats area). The value `0x46` (`'F'`)
  in a home slot terminates the list.
* **League results** `R(L, r, p) = FAR:6dc8 + (r + 38*L)*20 + p` (`r` = 1-based round, so `r = 1` is
  `FAR:6ddc`, save block 6). Even `p` = home goals and odd `p` = away goals, both `i8`. The value
  `0x1e` in the home byte means "postponed / not to be played now".
* **Cups** `c` in 0..3 (0 = DFB-Pokal, 1..3 = European cups; the relegation match uses cup 1). Pairings
  `FAR:76ca + 32*c + p` (home) and `+p+1` (away) (block 28). Scores `FAR:4c7e + 32*c + p` and `+p+1` (`u8`,
  block 33). The match engine addresses cups as `cc = c + 10`, so cup scores are `FAR:4b3e + 32*cc + p`.
  **Score encoding:** the home score gets `+10` when extra time is played and `+20` after a penalty
  shoot-out (the stored score is then the shoot-out score). Displays reduce the home value modulo 10.
* `DS:07d6[r]` = number of pairings of cup round `r` (`32,16,8,4,2,1`). `FAR:0008` = DFB cup round and
  `FAR:0009` = European cup round. The relegation match sets `FAR:0009 = 5`.
* **Goal-minute tables** (transient): league `G(L, p, k) = FAR:515c + (20*L + p)*8 + k`, cups
  `G(cc, p, k) = FAR:433c + (32*cc + p)*8 + k` = `FAR:4d3c + (32*c + p)*8 + k`, with `k` in 0..7.
  Odd `p` holds the away team's minutes.

## 1. Overview: how a match day is played

```
season_main_loop 2a58:3176
 ├─ matchday_title_league(mask) 1310:0995 ─┐
 ├─ matchday_title_dfb_cup(mask) 1310:0261 ┤
 ├─ matchday_title_european_cup 1310:0290  ┼─► matchday_play(league_mask, cup_mask, 0, 0) 1310:15db
 ├─ matchday_relegation_match 1310:02bf ───┤      ├─ per pairing: 2a58:20b2 (gate money, forfeit, live registry)
 └─ matchday_play_rescheduled 1310:07a2 ───┘      ├─ match_live_period(.., 1, 45) 1310:2303
                                                  ├─ match_live_period(.., 46, 90)
                                                  └─ cups: cup_round_helper 27c2:1226 → extra time
                                                       (91..105, 106..120) → penalties 1310:356d
match_live_period(from, to):
  for every pairing:  match_simulate_quick_result (1f9d:08e9)  → number of CHANCES per side,
                      goal_minutes_generate (1310:12fe)        → one random minute per chance
  for minute = from..to:
      for every pairing: card/injury events (1310:2ee5, human matches only)
                         for each scheduled chance minute == minute:
                             match_goal_chance (1f9d:0c3b) → GOAL or miss (RNG),
                             live human match → match_ticker_events 2a58:0ca3 (scorer, TORE scene)
  at minute 90: league table update 3a41:2d33 and AI scorers 24a4:1662
```

The result of every match (AI and human alike) is decided by the same two steps:

1. **Chances per half** (`1f9d:08e9`). `d = sh/3 - sa/3`, where `sh` and `sa` are the
   `team_strength_value(team, 1, from)` values. The leading side draws `r1 = rr(1, mx)` chances
   (or `max(r1, r2)`), the trailing side gets `rr(0, 2)`, and both get noise. The counts are capped
   and then scaled by `(to - from)/45`, truncated. That is 44/45 for the first half and 44/45 for
   the second half, so a single chance is lost.
2. **Conversion** (`1f9d:0c3b`) at each scheduled minute. The attacking advantage is
   `adv = (attack(kind 2) - opponent defence(kind 0))/3`. The home side first needs `rr(0,4) > 1`
   (3/5) and the away side needs `rr(0,1) != 0` (1/2). Then, if `adv > 0`, the chance is a goal when
   `rr(0, (adv>>2)+2) != 0`. Otherwise it is a goal when `rr(0, (-adv)>>2) == 0 || rr(0,6) == 0`.

There is no separate home-advantage constant. The home advantage is the asymmetric pre-check (3/5 for
the home side against 1/2 for the away side) plus the extra `rr(0,3)` chances for the home team in
`08e9`.

The 8-bit `IMUL` (07a2 at 08d4/08d6 and 095f/0961: `MOV AL,0x14; IMUL byte ptr ES:[0x225a]`, ES = `[0x98de]` = 5cb3 = DGROUP)

### 1310:0b24 `team_swap_slots`

`void far (u8 a, u8 b, u8 with_refs)`. Callers: `league_shuffle_teams`, `start_menu_new_or_load`
18bc:2184, `season_main_loop`. If `a > 0x3f || b > 0x3f`, it returns without doing anything. Otherwise
it exchanges every reference to club slots `a` and `b`:

1. `pdb(i).club` (`FAR:5801 + 0x25*i`) for `i` in 1..0x96: `a ↔ b`.
2. `mgr(m).team` for `m < DS:07ab`: `a ↔ b`.
3. If `with_refs`: `swap_team_ref_byte(&DS:07ac..&DS:07b0, a, b)` (5 bytes, 1-based refs).
4. Swaps the club records `FAR:3066+0x22*t` (34 bytes) through a temporary block from `mem_alloc`.
   `fatal_error_exit(4)` if the allocation fails.
5. Swaps the team tables `FAR:0ecc+0x36*t` (54 bytes, same way, block 16), `FAR:9d36+0x15*t` (21 bytes),
   `FAR:a2ca+8*t` (8 bytes) and `FAR:a4ca+8*t` (8 bytes).
6. `team_swap_in_table_a4ca(a, b)`.
7. For `m < DS:07ab`: swaps the 10-byte records `FAR:9336 + 10*(64*m + a)` and `+ 10*(64*m + b)`.

  * `FAR:5396[2m] = 1`, `FAR:5397[2m] = 2`, `FAR:1d1c[6m..6m+5] = 0x7f`, `FAR:2e99 = 1`.
  * `FAR:305c[k] = c`, `FAR:0028[k] = p`, `FAR:4bf0++`.

  For a home match it also has a 1-in-`(4*(30-x)+15)` chance (`x` = clamped mood) to set
  `mgr(m).+0x13e |= 1`. Its RNG calls and the ledger writes belong to the finance area.

### 4.3 27c2:1226 `cup_round_helper(cmask, cnt, after_et)` (cup area)

It clears `FAR:1d14[m]` for all managers. For each cup `c` in the mask and each pairing `k`:

* DFB cup (`cmask == 1`): if `S[0] == S[1]` or `S[0] - S[1] == 10` (still level after extra time),
  it sets `found`, adds `+10` to `FAR:4c7e[k]` (indexed without the cup offset; DFB is cup 0), sets
  `FAR:1d13[mi] = 1` and `FAR:2e99 = 1` for a human club, and calls
  `match_penalty_shootout(c, k, cmask, mi & 0x7f)` when `after_et`.
* Two-leg cups: if `FAR:1d17[c] != 0` (second leg) and `cup_pairing_helper(c, k) == 0x1e` (aggregate
  level), it does the same, without `FAR:1d13`.

It returns `found`.

### 4.4 League table

At the final whistle (`to == 90`) `match_live_period` calls `3a41:2d33(L, 0, 1)` for every played
tier. This applies round `DS:225a[L]-1` (results `!= 0x1e`): points `+DS:2271` per win (2 or 3), 1
per draw, goals, games, win/loss counters, series counters `FAR:9d36`, and head-to-head `FAR:9336`.
It then sorts `FAR:535a` by points, games (unless `DS:224d`), goal difference and goals scored.
It also calls `24a4:1662(L)`, which gives the goals of the AI clubs to scorers (RNG). Both are
specced in [stats.md](stats.md) §2.3 and §3.2.

## 7. Open questions

1. `match_schedule_goal_minutes` (1310:12fe) uses the league table for the cup duplicate check, so cup
   chance minutes may repeat and the RNG call count depends on unrelated FAR memory (about
   FAR:579c..6174). A bit-exact port needs a flat FAR memory model. Verified in the disassembly.
2. `match_simulate_quick_result` checks `FAR:6dc8[(DS:225a[c] + 38c)*20 + p] == 0x1e` also for cups
   (`c = 10..13`). This reads `DS:2264..2267` and FAR memory around 0x8e00. Which values can occur
   there in practice (could a cup match be skipped)? Note: the access is `ES:[BX+0x225a]` with
   ES loaded from the selector slot `[0x9b24]` (1f9d:0929). That slot holds 0x5cb3 (DGROUP), as does
   `[0x98de]` used by 1310:07a2, so the address really is `DS:225a+c` (checked with read_memory). For
   `c >= 10` the byte read is therefore `DS:2264..2267`, i.e. it is in DGROUP, not out of the segment.
3. `match_live_period` simulates chances for **all three** tiers even when `league_mask` has fewer bits
   (RNG consumed and goal-minute tables filled). In the minute loop, cup days with `cup_mask > 1`
   process cups 1..3 regardless of the mask. Confirm with a trace that this matches gameplay; both
   readings are from the disassembly.
4. Pausing (space, or a click at `FAR:6dc0 == (0,0)` with `FAR:2ea2 == 1`) skips the whole minute,
   including its chances. The meaning of the `(0,0)` test (the mouse struct layout) is unconfirmed.
5. `matchday_play_rescheduled` clears only 19 of the 20 temporary result bytes and stores the
   temporary results in round `DS:225a[0]` of tier 0. Check against a save that has rescheduled games.
6. `FAR:21d8[2*mi]` for `mi >= 0x81` (an away human club matched via the second argument) would write
   out of range. `match_simulate_quick_result` passes `(team, 0xff)`, so this never happens there, but
   `match_handle_panel_click` uses `(0xff, team)` and masks with 0x7f.
7. The semantic names of the player attributes `+0x10/+0x11/+0x12` and of `mgr.+0x131`/`+0x13d`
   (taken here as skill / condition / extra and morale / discipline) need confirmation by the squad
   area.
8. 2a58:0ca3, 2a58:20b2, 2a58:042f/009d/1f75 (segment 2a58) are only described by contract here.
   Their full UI layout (panel bitmaps from PIC 8, `blit_bitmap` coordinates) is not specced.
